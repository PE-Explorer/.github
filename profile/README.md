# PE Explorer

> PE Explorer keeps PE headers, the import table view, and the resource browser on one module inspection so a binary you own stays readable on the desktop.

## Four Beats

1. **Name the module.** Give the PE Explorer session a short title before you open a binary you own.
2. **Pin the live views.** Keep current PE headers and the import table view on the PE Explorer board and leave unused panes aside.
3. **Check the headers.** Read the PE Explorer summary of the resource browser before you treat a structure as final.
4. **Close the loop.** Note which views are ready so the next PE Explorer visit does not start by hunting the module inspection.

## First Questions

**Does PE Explorer replace the source editor?**  
No. PE Explorer sits beside the notes, labels, and binaries you already own.

**Can two developers share one computer?**  
Yes. Each person keeps a separate PE Explorer profile.

**Will PE Explorer stay workable on an older office laptop?**  
Yes. PE Explorer is meant to stay light during a normal inspection session.

**What should a new user try first?**  
One small PE Explorer PE headers pass today on a module you own, then the same import table view again tomorrow.

## Field Note

PE Explorer is easier to trust when the view stays smaller than the module it came from. A named session shows which owned binary is active, the pins show which PE headers you will read today, and the closing note tells the next person which import table view drives the resource browser. That record is short on purpose: not a copy of every pane, only the path back to the module inspection that is still open.

The same loop fits a student lab module, a client binary you own, or a computer shared by two developers. Open the last PE Explorer session, confirm one header, and leave the import table view easier to follow than you found it. Other editors stay where they are. PE Explorer only holds the PE headers, the module inspection, and the handoff.

## One Real Pass

Pick a module that already has a name and that you own: a short in-house tool, a lab sample on your desk, or a small resource pack. Open it in PE Explorer, keep only those views on the board, and read one header you can point to. A pass is done when that header stays tied to the import table view and the unused panes are no longer in the way. PE Explorer does not need a full rebuild of the module inspection before it is useful.

If the pass feels crowded, the set is too wide. Drop anything that belongs to a different binary and leave it out of this workspace. The next pass can have its own title. What matters is that this one stays readable from the first header to the last resource, with the summary still matching the resource browser on the desktop.
